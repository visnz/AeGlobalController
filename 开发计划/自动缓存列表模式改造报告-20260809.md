# 自动缓存列表模式改造报告

日期：2026-08-09

## 需求与目标

1. 修复 Cache 页面内容靠下、出现大块空白的问题。
2. 让开始缓存入口在页面顶部明确可见。
3. 移除用户不易理解的自动依赖树展示和自动深度排序。
4. 改为用户手动维护缓存列表：添加当前合成、单项启用/停用、调整顺序，再按列表顺序批量加入渲染队列。

## 实现摘要

- `src/ui.jsx`
  - Cache 页面改为 `alignment:['fill','top']`，减少无意义的纵向填充。
  - Cache 控件改为逐个调用 `add()` 创建，避免 ScriptUI 资源字符串解析失败。
  - 列表双击改为原地更新条目文字，并在切换到 Cache 页时自动激活列表，避免焦点跳到排序按钮后必须重新点击列表。
  - Cache 页操作按钮、分页按钮改为中文，排序按钮使用 `↑` / `↓`。
  - 新增顶部 `Add Selected`、`Start Cache`、`Refresh` 操作行。
  - 依赖树说明改为扁平的 `Cache List`。
  - 列表下方增加 `Up`、`Down`、`Remove`，用于维护执行顺序和删除项目。

- `src/tools.jsx`
  - `OF_Tools_initCachePanel()` 改为维护当前窗口内的手动列表，不再自动递归扫描子合成。
  - `Add Selected` 使用当前活动合成（或 Project 面板选中的合成），按合成 ID 去重。
  - 双击列表项切换启用状态；`Start Cache` 只处理启用项，并严格按照列表顺序调用原有缓存流程。
  - 保留原有 `_pre` 创建、父级引用替换、渲染队列和 MOV 导入逻辑，避免破坏已有缓存机制。
  - 原依赖树函数暂时保留，供兼容或后续恢复使用，但新 UI 不再调用它们。

- 根目录 `visnlink.jsx`
  - 已按 `build.sh` 中的 9 个源文件顺序重新构建。

## 方案取舍与注意事项

- 列表目前只在当前面板窗口生命周期内保存，尚未持久化为工程或 `app.settings` 配置。
- `Start Cache` 现在会同步执行 AE 渲染，渲染完成后立即导入 MOV；重复缓存时会复用已有 FootageItem，不重复导入同一个文件。
- 用户需要自行决定父合成、子合成的顺序；脚本不再保证依赖深度顺序。
- 旧的依赖树辅助函数没有删除，以减少潜在兼容风险。

## 待验证项

1. 在 AE 中确认 Cache 页面顶部按钮和 Template / Cache Folder 是否都位于可视区域。
2. 添加多个合成后测试双击启用、`Up` / `Down` 排序和 `Remove`。
3. 关闭部分列表项后，确认 `Start Cache` 只处理启用项。
4. 测试同一合成重复添加时是否正确去重。
5. 按用户指定顺序缓存父子合成，确认现有 `_pre` 替换逻辑不会产生意外引用。
