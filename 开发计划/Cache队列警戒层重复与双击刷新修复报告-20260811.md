# Cache 队列警戒层重复堆积 + 双击刷新不生效修复报告

日期：2026-08-11

## 背景

用户实测上一轮的 marker comp 持久化方案后反馈两个新问题：

1. Cache 面板双击列表项切换启用/禁用，画面没反应（连日志都没有变化的痕迹），要点一下别的地方再点回来才刷新。
2. `_OF_CacheQueue` 内部合成里堆了十多条警戒文字层，而设计上应该始终只有一条、置顶。同时警戒文字太长，要求缩短或拆成两句。

## 分析

### 警戒层重复堆积

`OF_Tools_saveCacheQueueForProject` 每次保存都会先从上到下删掉 marker comp 现有的所有层，再重新加回队列层 + 一条新警戒层。但警戒层在 `OF_Tools_addCacheQueueWarningLayer` 里被设成了 `locked = true`，而删除循环是：

```js
for(var i = markerComp.numLayers; i >= 1; i--){
    try { markerComp.layer(i).remove(); } catch(e){}
}
```

`Layer.remove()` 在层被锁定时会抛异常，这里用空 `catch(e){}` 直接吞掉——旧的警戒层因此从来没有真正被删掉，而每次 `persist()` 都会在末尾追加一条新的警戒层，久而久之越攒越多。队列层本身不锁定，不受影响，所以只有警戒层会重复。

### 双击不刷新

对比面板里其它会改变 `cacheItems` 的操作（`addComp`/`moveUp`/`moveDown`/`removeItem`/`refresh`），全部是改数据后调用 `refreshList(idx)`（`removeAll()` 再逐条 `add()`，强制整个列表重绘）。只有 `onDoubleClick` 是个例外：直接改 `panel.list.items[idx].text`，注释里写的原因是"避免 removeAll/add 让焦点跳到其它按钮"。但这个宿主环境下直接改 `ListItem.text` 不会立即触发重绘，要等下一次无关的焦点切换才能看到效果，这正是用户看到的现象。

## 修复（`src/tools.jsx`）

1. `OF_Tools_saveCacheQueueForProject` 的删层循环里，删除前先尝试解锁：
   ```js
   try { oldLayer.locked = false; } catch(e2){}
   oldLayer.remove();
   ```
   解锁之后 `remove()` 能正常执行，每次保存都能把上一次的警戒层真正清掉，配合末尾"重建后只加一条"的逻辑，之后每次保存都只会有一条警戒层。
2. `OF_TOOLS_CACHE_QUEUE_WARNING_TEXT` 缩短并拆成两行（用 `\r` 分段）：`"⚠ visnlink Cache 队列数据\r请勿删除/改名/移动"`；层名单独用一个不含换行的短字符串 `OF_TOOLS_CACHE_QUEUE_WARNING_NAME`（`"⚠ 请勿删除 - Cache 队列数据"`），避免 Timeline 图层名里出现换行符看起来很怪。
3. `panel.list.onDoubleClick` 改成跟其它按钮一致的写法，切换 `enabled` 后调用 `refreshList(idx)` 而不是手动改 `.text`；`refreshList` 内部本来就会在结尾恢复选中项并设 `panel.list.active = true`，不会有焦点跳走的问题（其它四个按钮已经这样用，没出现过相关反馈）。

## 已知取舍 / 后续

- 用户当前工程里已经存在的十多条重复警戒层不会被这次修复自动清空——下一次任何触发 `persist()` 的操作（增删/排序/勾选/跑一次 Start Cache）会先把 marker comp 里**所有**层（包括这些残留的警戒层）解锁并删除，再重新加回队列层 + 一条新警戒层，所以会自然收敛成一条，不需要用户手动去 Project 面板里逐条删。
- 没有改动 `OF_Tools_addCacheQueueWarningLayer` 本身的"无条件 addText"逻辑——它依赖的前提是"调用前 marker comp 已经被清空"，这个前提现在由删层循环的解锁修复保证成立，不需要额外加"先查是否已存在同名层再决定加不加"的判断，避免多一层没必要的复杂度。

## 待验证

1. 装进 AE，在已经堆积了十多条警戒层的旧工程里做任意一次队列操作（比如切换一次勾选），保存后打开 `_OF_CacheQueue`，确认只剩一条警戒层，且文字变成两行的短版本。
2. 双击 Cache 面板列表项，确认勾选框状态立刻可见地切换，不需要先点别的地方。
3. 反复多次双击/增删/排序，确认警戒层始终维持一条、不再随操作次数增长。
4. 确认警戒层文字层名（Timeline 里显示的名字）是短的单行文字，没有换行符导致的显示异常。
