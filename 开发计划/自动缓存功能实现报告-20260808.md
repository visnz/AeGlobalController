# 自动缓存功能实现报告

日期：2026-08-08

## 已实现内容

### 1. 批量工具函数（`src/tools.jsx`）

新增以下函数：

- `OF_Tools_openCacheManager()`：打开 Cache Manager 窗口。
- `OF_Tools_getSelectedComps()`：获取当前活跃合成或 Project 面板中选中的合成。
- `OF_Tools_resolveCompForTree(comp)`：把 `_pre` 合成本地解析为原合成；失败则全局按名搜索。
- `OF_Tools_collectCompDependencies()`：递归收集依赖树。
- `OF_Tools_getDepthSortedComps()`：按深度降序排列（叶子优先）。
- `OF_Tools_cacheOneComp()`：单个合成缓存主流程。
- `OF_Tools_cacheCompList()`：按顺序批量缓存。
- `OF_Tools_findOrCreatePrecomp()`：查找/创建 `CompName_pre`。
- `OF_Tools_replaceParentSource()`：把引用原合成的层替换为 `_pre`。
- `OF_Tools_ensurePrecompLayers()`：维护 `_pre` 内的原合成层 + 清除旧缓存层。
- `OF_Tools_renderCompToMOV()`：加入渲染队列并阻塞渲染。
- `OF_Tools_applyCineFormRGBA16()`：套用 CineForm 输出模块模板。
- `OF_Tools_importAndPlaceMOV()`：导入 MOV 并放到 `_pre` 顶层 solo。
- `OF_Tools_getCacheFolderPath()` / `OF_Tools_promptAndSaveCacheFolder()`：缓存路径读写。
- `OF_Tools_findPrecompByName()` / `OF_Tools_getOrCreateCacheFolder()` / `OF_Tools_getProjectNameForCache()`：辅助函数。

### 2. UI（`src/ui.jsx`）

- batch 行新增 `Cache` 按钮。
- 点击打开独立的 `Cache Manager` 窗口，不在主面板占用太多空间。

### 3. 缓存路径

```
<用户缓存根目录>/<工程名>/Cache/<CompName>_cache.mov
```

- 工程名从 `app.project.file.name` 去掉 `.aep`/`.aepx` 得到。
- 未保存工程时使用 `Untitled`。
- 缓存根目录通过 `Folder.selectDialog` 首次设置，存储在 `visnlink.cacheFolderPath`。

### 4. 输出模块

- 优先套用模板 `OF_Cache_CineForm_RGBA16_Q4`。
- 未找到时尝试几个常见模板名，最后提示用户手动创建模板。
- 由于不同 AE 版本输出模块 JSON key 可能不同，未硬编码完整 JSON，而是依赖模板机制。

## 与计划的主要一致点

- 单独 Cache Manager 窗口。
- 按依赖深度排序，先缓存内部合成。
- `_pre` 本地解析优先、全局搜索回退。
- 缓存路径按工程名隔离。
- 主面板只保留一个 `Cache` 按钮。

## 待验证

1. 在 AE 2022+ 中创建输出模块模板 `OF_Cache_CineForm_RGBA16_Q4`（QuickTime / GoPro CineForm / RGBA 16bit / Quality 4）。
2. 测试单合成缓存：
   - 点击 `Cache` -> 选择缓存目录 -> Manager 显示依赖树。
   - 点击 `Cache Selected` -> 渲染完成后 `_pre` 结构是否正确。
3. 测试多层 PSD 结构：
   - 上层合成 -> 下层 `_pre` -> 原合成。
   - 再次缓存同一合成时，不重复创建 `_pre`，只更新 MOV。
4. 测试误选 `_pre` 时的本地解析。
5. 测试渲染失败时的异常提示。
6. 确认 `layer.replaceSource(precomp, true)` 在目标 AE 版本中可用。

## 已知局限

- 输出模块未硬编码完整 JSON，首次使用前需要用户手动创建模板 `OF_Cache_CineForm_RGBA16_Q4`。

## 更新记录（同日修复）

根据实测反馈：

1. **改为只添加到渲染队列**：删除 `app.project.renderQueue.render()`，不再阻塞 AE；用户手动在渲染队列里点击渲染。
2. **修复输出模块 / 输出路径被重置问题**：
   - 先 `om.applyTemplate(...)` 套用模板，再 `om.file = new File(movPath)` 设置路径。
   - 如果找不到模板，移除已加入的队列项并 alert，避免留下 Lossless 项。
3. **未渲染时的 fallback**：如果缓存 MOV 还不存在，`_pre` 里的原合成层会保持可见；等手动渲染完再次点击 Cache，MOV 会被导入并替换到顶层，同时原合成层隐藏。
4. **新增 Log 面板**：
   - 主面板底部新增 `Log` 开关按钮，点击展开/收起日志区域。
   - Cache 相关函数（打开 Manager、收集依赖、创建 precomp、渲染入队、导入 MOV、异常等）都会写入日志，方便排查“点了没反应”等问题。
5. **继续排查 Cache Selected 无响应**：在 `Cache Selected` 回调入口和确认对话框前后都加了日志，并把整个回调包在 try/catch 中，任何异常都会写入日志。
