# 自动缓存队列渲染隔离、失效清理与工程持久化报告

日期：2026-08-10

## 问题

1. 点击 Start Cache 渲染当前缓存队列时，AE 渲染队列（Render Queue）里之前残留的其它 `render=true` 项也会被一起渲染，导致之前勾选/加入过的合成被重复输出。
2. Cache 面板的列表条目持有 CompItem 引用；如果对应合成在 AE 工程里被删除，条目仍然留在面板列表里（访问其属性才会报错），刷新按钮原本只重新读取缓存目录和 `_pre` 状态，不校验条目是否还存在。
3. Cache 面板的队列是纯内存变量，关闭工程重新打开后列表清空，需要每次手动重新添加。

## 修复

1. `OF_Tools_renderCompToMOV()`：调用 `renderQueue.render()` 前，遍历队列把除本次新加入项以外所有 `render=true` 的项临时设为 `render=false`，渲染结束后恢复原状；本次临时加入的队列项渲染完成（无论成功失败）后立即 `remove()`，避免残留占用队列。
2. Cache 面板新增 `OF_Tools_isCompValid(comp)`：通过 try/catch 访问 `comp.id` 判断底层 Item 是否已被删除。Refresh 按钮现在会用它清除列表里已失效的条目，并按 `comp.id` 而不是名字做匹配/去重（工程里可能存在同名的不同合成，用 id 更可靠）。
3. 新增 `OF_Tools_getProjectQueueSettingKey()`（基于工程文件完整路径算简单 hash）、`OF_Tools_saveCacheQueueForProject()` / `OF_Tools_loadCacheQueueForProject()`，用 `app.settings` 的 `visnlink` 命名空间按工程分别持久化队列（存 `{id, enabled}` 列表，`JSON.stringify`/`JSON.parse`）。面板初始化时自动加载，增删/排序/勾选/缓存完成后都会保存。未保存过的工程（没有 `app.project.file`）不做持久化，只在当前会话内存里维护。

## 待验证

1. 手动往 AE 渲染队列加几个别的合成并保持勾选，再在 Cache 面板点 Start Cache，确认只输出面板列表里勾选的项，渲染完成后手动加入的那几项状态和勾选框恢复原状。
2. 在 Cache 面板加入合成后，去工程里删除其中一个合成，点 Refresh，确认对应条目从列表消失且不报错；工程里另建一个同名合成，确认不会被误认成同一条目。
3. 加入几个合成、调整顺序/勾选状态后保存工程，关闭 AE 重新打开该工程，确认 Cache 面板列表和顺序、勾选状态自动恢复。
4. 未保存过的新工程里操作 Cache 面板，确认不报错（仅本次会话内有效）。
