# 自动缓存功能开发计划

日期：2026-08-08

## 需求背景

复杂合成（如含三维层）在 AE 里播放卡顿。通常做法是渲染成 MOV 缓存，再替换到父合成中。但 AE 自带的 `Export & Replace` 会直接把所有引用替换成 MOV，更新原始合成后需要重新手动导入替换。

本功能希望建立中间层结构：
```
Comp2/3 -> CompName_pre -> CompName（原合成）
```
- `CompName_pre` 里：顶层是缓存 MOV（solo），底层是原合成（enabled=false）。
- 后续更新缓存时，只需要重新渲染最内层 `CompName`，`CompName_pre` 里的 MOV 会自动被覆盖更新。

## 目标

在 `Tools` 区新增一个 `Cache` 按钮，点击打开独立的 **Cache Manager** 窗口，实现：
- 对当前活跃合成或 Project 面板多选合成批量生成缓存。
- 递归展开子合成，按依赖深度排序（先缓存内部，再缓存上层）。
- 自动创建/复用 `CompName_pre` 预合成，并替换父级引用。
- 渲染为 GoPro CineForm MOV（RGBA 16bit，Quality 4）。
- 缓存路径按当前工程名隔离，存储在 `visnlink` 设置中。

## 核心流程

1. **获取目标合成**
   - 优先当前 viewer 活跃合成。
   - 否则收集 Project 面板中选中的 `CompItem`。

2. **解析源合成（处理误选 `_pre`）**
   - 若选中 `CompName_pre`，先查看它内部图层，找到 `layer.source` 为 `CompName` 的图层返回。
   - 本地找不到时，全局按 `CompName` 搜索回退。

3. **收集依赖树**
   - 递归遍历每个目标合成内部的子合成。
   - 遇到 `_pre` 合成时，本地解析为原合成后再继续递归。
   - 用 `visited` 去重，记录每个合成的深度。
   - 最终按深度升序排序，叶子节点优先缓存。

4. **单个合成缓存**
   - 查找/创建项目文件夹 `Cache`。
   - 查找/创建 `CompName_pre`，尺寸/帧率/时长与原合成一致。
   - 在 `CompName_pre` 内：底层放原合成（enabled=false），顶层放/更新缓存 MOV（solo=true）。
   - 把项目里除 `CompName_pre` 自身外所有引用原合成的层替换为 `CompName_pre`。
   - 渲染原合成到 `<cacheRoot>/<projectName>/Cache/CompName_cache.mov`。
   - 导入 MOV 并放入 `CompName_pre` 顶层。

5. **渲染与输出模块**
   - 使用 `app.project.renderQueue.items.add(sourceComp)`。
   - 优先套用用户预存的输出模块模板 `OF_Cache_CineForm_RGBA16_Q4`。
   - 模板不存在时，尝试程序化 `setSettings` 设置 QuickTime / GoPro CineForm / RGBA 16bit / Quality 4；失败则提示用户手动创建模板。
   - 调用 `app.project.renderQueue.render()` 阻塞渲染。
   - 渲染成功后导入 MOV。

## UI 设计

### 主面板

在 batch 行追加一个 `Cache` 按钮：
```
batch: [MB] [+30s] [Cache]
```

点击 `Cache` 打开独立的 **Cache Manager** 窗口。

### Cache Manager 窗口

```
+--------------------------------------------------+
| Cache Manager                                    |
+--------------------------------------------------+
| Cache Folder: [路径...]              [Set...]   |
+--------------------------------------------------+
| Selected Comps:                                  |
| [x] Comp3 (depth 2)                              |
| [x]   Comp1 (depth 1)  [pre] [cached]          |
| [x] Comp2 (depth 1)                              |
| [ ]   CompA (depth 0)                          |
+--------------------------------------------------+
| [Refresh]  [Cache Selected (depth-first)]        |
+--------------------------------------------------+
```

- 顶部显示缓存根目录，`Set` 按钮可重新选择。
- 中间是带复选框的合成列表，默认全部勾选。
- 底部 `Refresh` 刷新列表，`Cache Selected` 按深度顺序执行缓存。

## 缓存路径

```
<用户选择的缓存根目录>/<当前工程名>/Cache/<CompName>_cache.mov
```

- 当前工程名从 `app.project.file.name` 去掉 `.aep`/`.aepx` 得到。
- 未保存工程时使用 `Untitled`。
- 这样切换工程无需重新设置缓存根目录。

## 待实现函数清单

全部放在 `src/tools.jsx`：

- `OF_Tools_openCacheManager()`：打开 Cache Manager 窗口。
- `OF_Tools_cacheSelected()`：入口（兼容旧单合成按钮，现改为打开 Manager）。
- `OF_Tools_getSelectedComps()`：获取目标合成列表。
- `OF_Tools_resolveSourceComp(comp)`：本地/全局解析 `_pre` 的源合成。
- `OF_Tools_resolveCompForTree(comp)`：依赖树专用的 `_pre` 解析。
- `OF_Tools_collectCompDependencies(comp, result, visited, depth)`：递归收集依赖。
- `OF_Tools_getDepthSortedComps(comps)`：按深度升序排列。
- `OF_Tools_cacheCompList(comps, cacheFolderPath)`：顺序缓存多个合成。
- `OF_Tools_cacheOneComp(targetComp, cacheFolderPath)`：单个合成缓存主流程。
- `OF_Tools_getOrCreateCacheFolder()`：项目内 Cache 文件夹。
- `OF_Tools_findOrCreatePrecomp(sourceComp, parentFolder)`：查找/创建 `_pre`。
- `OF_Tools_replaceParentSource(sourceComp, precomp)`：替换父级引用。
- `OF_Tools_renderCompToMOV(comp, movPath)`：渲染到 MOV。
- `OF_Tools_applyCineFormRGBA16(om)`：配置输出模块。
- `OF_Tools_importAndPlaceMOV(precomp, movPath, sourceComp)`：导入 MOV 并放置到 `_pre`。
- `OF_Tools_getCacheFolderPath()`：读取设置里的缓存根目录。
- `OF_Tools_promptAndSaveCacheFolder()`：弹出文件夹选择并保存。
- `OF_Tools_updateCachePathUI(myPalette)`：刷新主面板路径文本。

## 边界情况

| 场景 | 处理 |
|---|---|
| 未选中合成 | alert 提示 |
| 缓存根目录未设置 | 自动弹出 Folder 选择框；取消则返回 |
| 选中 `_pre` | 本地解析内部原合成；失败则全局搜索 |
| `_pre` 内容被误删 | 通过原合成名搜索并重新添加底层原合成 |
| `CompName_pre` 已存在 | 复用，只更新 MOV 层 |
| 缓存 MOV 已存在 | 渲染直接覆盖 |
| 渲染失败 | try/catch 捕获并 alert |
| 循环引用 | `visited` 去重 |

## 风险与验证

- 输出模块 JSON 在 AE 各版本中可能有差异，优先依赖用户模板 `OF_Cache_CineForm_RGBA16_Q4`。
- `app.project.renderQueue.render()` 是阻塞式渲染，会卡住 AE UI；已在计划中加入渲染前确认提示。
- 需要验证 `layer.replaceSource(precomp, true)` 在 AE 2022+ 中可用。
- 后续在 AE 中实测：多层 PSD 导入结构、重复缓存、工程切换。
