# 批量缓存合并 render() 调用、一次性点掉覆盖确认框报告

日期：2026-08-10

## 背景

用户确认上一轮修复后 "Undo group mismatch" 警告不再出现了。但批量缓存时，AE 的"文件已存在/覆盖"确认框仍然每缓存一个合成就弹一次，需要手动点一下才能继续，没法一键跑完整个队列。用户提出：能不能把整个队列一次性推进 AE 的渲染队列，让确认框一次性连续弹出，自己一口气点掉。

## 分析

根因是调用 `renderQueue.render()` 的方式：之前的实现里，每个合成单独走一轮"建临时队列项 → 调一次 `render()` → 渲染完立即移除队列项 → 处理下一个合成"，也就是**每个合成各自触发一次独立的 `render()` 调用**。AE 的覆盖确认框是绑定在每一次 `render()` 调用上的——所以调了 N 次 `render()`，就有 N 次独立的确认弹窗，脚本每次都要等用户点完这一次才能继续处理下一个合成。

用户建议的思路是对的：如果把这一批要缓存的合成**全部**先加入渲染队列，再只调用**一次** `render()`，AE 处理整条队列时如果遇到需要确认的项，会在这一次调用的过程中连续弹出，用户可以不间断地连续点掉，而不必等脚本在两次弹窗之间做别的事情。

## 修复（`src/tools.jsx`）

把原来"渲染 + 建队列项"耦合在一起的 `OF_Tools_renderCompToMOV` 拆成两个函数：

- `OF_Tools_enqueueRenderItem(comp, movPath)`：只负责建队列项、套模板、设输出路径，不触发渲染，返回队列项对象。
- `OF_Tools_renderQueueItemsBatch(rqItems)`：接收一批队列项，临时关闭渲染队列里不属于这一批的其它已勾选项，**只调用一次** `app.project.renderQueue.render()` 处理传入的所有项，结束后恢复被临时关闭的项。渲染过程中出现的异常不再直接 `throw`（因为批量渲染里某一项失败或被中途 Stop，不代表其它项也失败），而是记日志，每一项各自的成败交给调用方按 `rqItem.status` 逐个判断。

原来的 `OF_Tools_cacheOneComp`（单合成建 precomp → 渲染 → 导入 一条龙）拆成两段：

- `OF_Tools_prepCacheEntry(targetComp, cacheFolderPath)`：建/找 precomp、替换引用、摘除旧素材引用、把旧缓存文件改名备份成 `.bak`，返回一个描述这次缓存任务的 `entry` 对象（`sourceComp`/`precomp`/`movPath`/`bakPath`/`hasBak`），不做渲染。
- `OF_Tools_importCacheEntry(entry, rendered)`：按渲染结果导入 MOV 并切层，或者渲染失败时启用原合成 fallback + 还原 `.bak`（逻辑和上一轮的备份策略一致，只是从单合成场景搬到了批量场景）。

`OF_Tools_cacheCompList(comps, cacheFolderPath)` 重写为三段：

1. 依次对每个合成调用 `OF_Tools_prepCacheEntry`，收集 `entries` 数组（某一项准备失败就跳过并记日志，不影响其它项）。
2. 依次对每个 `entry` 调用 `OF_Tools_enqueueRenderItem`，把这一批全部加进渲染队列，再统一调用一次 `OF_Tools_renderQueueItemsBatch`。
3. 渲染调用结束后，逐个读取每个 `entry.rqItem.status`（`RQItemStatus.DONE` 才算成功，同时校验文件确实存在），移除临时队列项，再调用 `OF_Tools_importCacheEntry` 做导入或 fallback。

这样即使批量渲染中途被用户按 Stop 打断，已经渲染完的项状态是 `DONE`，会正常导入；还没轮到渲染的项状态还是排队中，会走 fallback + 还原备份，不会误判为"渲染成功"，也不会丢失任何一项的旧缓存。

## 待验证

1. 批量勾选多个合成（其中几个是第二次缓存、本地已有旧 MOV），点 Start Cache，确认所有"文件已存在/该文件正被工程使用"的确认框在一次渲染过程里连续弹出，可以不间断地依次点掉，不需要等脚本单独处理完一个合成再触发下一个弹窗。
2. 中途故意点"停止"打断批量渲染，确认已经渲染完的合成正常导入替换，还没渲染到的合成走 fallback（原合成层重新启用）且各自的 `.bak` 备份被还原回原文件名，没有数据丢失。
3. 确认渲染队列面板在缓存过程中和结束后都没有残留本次批量加入的临时队列项。
4. 再检查一次 Ctrl+Z 撤销粒度，确认批量缓存多个合成后，仍然能按合成分别撤销"导入 MOV/切层"和"建 precomp/替换引用"，两两之间不会因为渲染阶段被合并成一次调用而混在一起。
