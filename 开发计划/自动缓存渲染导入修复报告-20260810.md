# 自动缓存渲染与导入修复报告

日期：2026-08-10

## 问题

1. 工程目录名出现 `%E9%80...` URL 编码，缓存路径不符合预期。
2. 第一次点击 Start Cache 只加入 Render Queue，没有立即生成或导入 MOV。
3. MOV 层被放在 `_pre` 底部。
4. 重复点击时，同一个 MOV 被重复导入，触发多次 AE 导入提示。

## 修复

- 新增缓存名称解码和非法文件名字符清理，项目名和合成名会先经过 `decodeURI` / `decodeURIComponent`，再生成缓存路径。
- `OF_Tools_renderCompToMOV()` 在设置 Output Module 后调用同步 `app.project.renderQueue.render()`，渲染完成后返回实际文件。
- `OF_Tools_cacheOneComp()` 在同一次操作中完成渲染和 MOV 导入，不再要求用户第二次点击 Start Cache。
- `OF_Tools_importAndPlaceMOV()` 查找并复用同路径的已有 `FootageItem`，避免重复导入。
- MOV 层使用 `moveToBeginning()` 放到 `_pre` 顶层并 Solo；原合成层移动到底部并禁用。

## 待验证

1. AE 2023 中确认路径为 `<缓存根目录>\<解码后的工程名>\Cache\<合成名>_cache.mov`。
2. 确认第一次 Start Cache 完成渲染后，`CompName_pre` 顶层立即出现 Solo MOV 层。
3. 重复点击 Start Cache，确认不会重复创建同一路径的 FootageItem 或重复弹导入选项。
4. 批量缓存多个列表项，确认同步渲染顺序和每个 `_pre` 的层级状态。
