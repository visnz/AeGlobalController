# 缓存目录直达按钮与 Undo group mismatch 修复报告

日期：2026-08-10

## 问题

1. Cache 面板只能看到缓存目录路径文字，想直接在系统文件浏览器里打开当前工程的缓存输出目录，没有入口。
2. Start Cache 缓存导出完成、进行 pre 替换（precomp 创建/引用替换）阶段时，AE 报 `Undo group mismatch, will attempt to fix` 警告。

## 分析

原来的调用栈：`cacheAll.onClick` 用一个 `app.beginUndoGroup("Auto Cache") ... app.endUndoGroup()` 把整批合成的处理都包起来；批内每个合成又依次执行「建 precomp / 替换引用」→ `renderQueue.render()`（同步渲染）→ 「导入 MOV / 切层」。`renderQueue.render()` 是同步且不可撤销的操作，AE 在渲染时会自己管理内部状态；如果脚本在渲染调用发生时仍持有一个尚未关闭的 undo group（无论是外层这个大 group，还是理论上任何跨越 render() 调用的 group），AE 的 undo 计数会和自己内部渲染流程产生的操作对不上，于是报 "Undo group mismatch"，随后 AE 会尝试自动修复——但修复后的 undo 状态不可靠，后续脚本对文档的编辑（下一个合成的 precomp 替换）就可能在错乱的 undo 上下文里进行。

## 修复

1. `src/ui.jsx` `folderRow` 里新增一个「打开」按钮（`cp.folderRow.openBtn`），紧跟在「设置」按钮后面。
2. `src/tools.jsx` 新增 `OF_Tools_openCacheFolder()`：优先定位当前工程实际写入的 `<缓存根目录>/<工程名>/Cache` 子目录，若还没生成过（不存在）则回退打开缓存根目录，用 `Folder.execute()` 调起系统文件浏览器。`initCachePanel` 里给 `openBtn.onClick` 接上这个函数。
3. `OF_Tools_cacheOneComp()` 拆成三段：
   - 「准备阶段」（建/找 precomp、替换引用、清理旧缓存层）包在自己的 `beginUndoGroup("Auto Cache Prep: ...")` / `endUndoGroup()`（用 try/finally 保证一定关闭）里；
   - 中间的 `OF_Tools_renderCompToMOV()`（同步渲染）**不**包在任何 undo group 里；
   - 「导入阶段」（导入 MOV、切换图层可见性，或渲染失败时的 fallback）包在单独的 `beginUndoGroup("Auto Cache Import: ...")` / `endUndoGroup()` 里。
4. 去掉 `cacheAll.onClick` 里原来包住整个 `OF_Tools_cacheCompList(...)` 批量循环的外层 `app.beginUndoGroup("Auto Cache")`——这层本身就是横跨多次 render() 调用的大 group，是 mismatch 的直接原因，删掉之后靠每个合成内部各自的两段小 group 保证可撤销性即可。

## 待验证

1. Cache 面板设置好缓存目录后点「打开」，确认能直接跳到 `<根目录>/<工程名>/Cache`；还没缓存过任何合成时点「打开」，确认回退打开根目录且不报错。
2. 批量勾选多个合成点 Start Cache，跑完整个队列，确认 AE 事件/控制台不再出现 "Undo group mismatch" 警告。
3. 缓存完成后用 Ctrl+Z 检查一次撤销的粒度：应该能分别撤销"导入 MOV/切层"和"建 precomp/替换引用"两步，而不是把整批合成的操作合并成一步或撤销行为错乱。
4. 故意让某一个合成渲染失败（比如输出模块模板配置错误），确认 fallback 启用原合成层这一步不受影响，后面排队的合成仍能正常继续处理，不会因为前一个的 undo group 状态残留而出问题。
